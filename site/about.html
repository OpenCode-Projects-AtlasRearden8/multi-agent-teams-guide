About This Guide

Multi-agent teams, explained like a friend would.

The one-paragraph version

Sometimes one AI agent is not enough — the task is too big, needs different skills, or genuinely benefits from a second opinion. This manual shows you how to run several AI agents together as a tiny staff: one agent plans, others do the work, one checks it, and they pass files to each other like coworkers leaving notes. You never need to write code. What you do need is a folder, a few plain-English documents, and a habit of reading what your agents actually wrote.

Who this is for

Absolute beginners who have already used one AI assistant (ChatGPT, Claude, Copilot, Gemini, or a local tool) and are wondering: what would change if I had two or three of these working together? You do not need programming experience. Every example here is a home or small-business project: reselling on eBay, launching a book, and taming household paperwork.

What you need

  • A computer, any age, any operating system.
  • One or more AI assistants you already have access to (web chats count!)
  • A normal folder on your computer (or on your desktop) for shared files.
  • 20 minutes for the first project, 10 minutes for the others.

The map of this guide

  1. When a team beats one agent — how to tell whether to bother with a team at all.
  2. Roles and handoffs — how to give each agent one clear job, and how they pass work along.
  3. Shared-file conventions — the folder rules that keep a team of agents from stepping on each other.
  4. Spotting confusion loops — what it looks like when agents get stuck in circles, and how to bail them out.
  5. Three worked projects — an eBay listing team, a book-launch team, and a household paperwork team, each written as a step-by-step walkthrough with sample files.
  6. Free tools and next steps — where to go from here without spending money.

Each page has a diagram. Each project is written so you can follow it with any AI tool — no special software required.

How this complements the agents-and-MCP handbook

Our companion book, the Agents-and-MCP Handbook, covers the single-agent story: what agents are, how tool calling works, and how MCP (Model Context Protocol) connects one agent to the world. That book is the one good employee. This guide is the org chart — orchestration basics: when to hire a second agent, how to divide the work, and how to keep the team honest. If you have not read that handbook, nothing here will break; just picture any AI assistant you have used when we say "agent."

The mental model in one sentence

Think of every agent as a polite contractor who works extremely fast, has no memory of yesterday, and will do exactly what you asked even if that was a mistake — so your whole job is to hand each one a clear note, a clear folder, and a clear definition of "done."

Yellow Post-It: education disclaimer

Everything in this guide is educational. It is not medical, legal, tax, or financial advice. Projects involving money, health paperwork, or anything regulated deserve a human expert. Always read what your agents produce before acting on it.

Ground rules used throughout

  • No secrets. Never paste accounts, passwords, or personal details (someone else's!) into an AI. Use fictional stand-ins like "Jane Doe, invoice #123" in your practice files.
  • Local-first. Everything lives in your own folder. No paid services needed for this book.
  • Readable by default. If an agent produced something you cannot skim in one minute, it is too complicated — send it back.
